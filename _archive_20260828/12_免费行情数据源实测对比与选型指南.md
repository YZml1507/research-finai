## 1. 为什么数据源选型是返工成本最高的决策（Phase 0-1 地基）

### 1.1 数据层是全链路的地基

个人量化系统的典型流水线是：**数据源 → 本地存储/缓存 → 特征与因子计算 → 回测/信号 → 组合与风控 → 模拟盘/实盘**。数据源位于最上游，它决定的不是"某一天的行情对不对"，而是三件会渗透到下游每一层的口径问题：

- **字段口径**：复权方式（前复权/后复权/不复权+因子）、财报披露日期有无、停牌日的表示方式（缺行 vs 空值 vs 前值填充）；
- **时间口径**：数据更新时刻（T+1 晚间更新 vs 盘后实时）、历史深度（分钟线能回溯多久）、单次请求上限与限流阈值；
- **频率口径**：能否拿到 1/5/15/30/60 分钟线——这直接决定"小时级信号"这条产品需求能不能成立。

这三件事一旦在 schema 与缓存层定型，下游所有特征、回测结果、评估指标都建立在它之上。换源不是"换个函数名"，而是**缓存重建 + 特征重算 + 回测结果全部作废**——这就是为什么数据源选型是整个项目返工成本最高的单一决策。

### 1.2 三个典型的"选型失误 → 全链路返工"场景

**场景一：复权口径选错。** 用"前复权"价格直接入库是最常见的开局。前复权价会随每一次新的除权除息事件整体平移——本地库里 2023 年的历史价格在某天突然全部变了，均线、回测净值、已算好的因子全部失真，只能全量重刷（详见第 4 章；博客园 2026-05 有一手踩坑记录，参考来源 [12]）。

**场景二：分钟线历史深度不足。** 策略设计时想做"小时级信号"，回测区间想要三年，结果发现所选源 1 分钟线只提供最近 5 个交易日（akshare 东财上游行为，官方 issue #5971 [16]），60 分钟线历史深度同样受限——信号频率实现不了，只能换源重爬（详见第 5 章矩阵）。

**场景三：关键字段缺失。** 想做"财报公告日对齐"以避免前视偏差，因子代码写完才发现所用的源只有"报告期"没有"实际公告日"，或公告日字段大量缺失——整张因子表全部重算（详见第 6 章）。

### 1.3 为什么必须在 Phase 0-1 敲定

- **调研阶段（未编码）改选型：成本≈0**——只需要重跑一次抽样验证。
- **缓存与 schema 定型后换源：成本=重写适配层 + 重建缓存 + 重算特征 + 重跑全部回测**，且复权/停牌口径差异会让前后两批实验不可比，等于实验日志作废。

因此正确姿势是：在 Phase 0-1 用最小的实验成本（本文第 9 章的统一实测方案，约 1-2 天编码量）敲定主源，并**从一开始就按"主源 + 校验源 + 本地缓存"的架构写数据适配层**，而不是单源硬编码。双源整合的一手实证（tushare issue #1857 [9]）显示，双源互补后数据获取成功率可从 85% 提升到 99% 以上，代价只是适配层多写一个 provider。

### 1.4 本文的立场

本文不冒充"已经替你测完了"。它做三件事：

1. 把散落在官方文档、GitHub issues、第三方实测文章里的事实，汇总成统一口径的对比矩阵（第 2-7 章），每个关键论断给出 ≥2 个独立来源或标注 [单源待证]；
2. 给出分场景的主源 + 校验源组合建议与 0~500 元/年成本估算（第 8 章）；
3. 给出 Phase 1 可直接执行的统一实测方案与验收标准（第 9 章），让你把本文所有"第三方口径"变成自己环境下的确定性结论。

**逐源点评：**

- **akshare**：广度之王，另类数据（龙虎榜、北向、舆情）几乎唯一免费选择；但接口本质是爬虫聚合，分钟线深度受上游窗口收紧影响明显（1 分钟线东财上游仅最近约 5 个交易日、新浪上游 9 个交易日 [#16]），复权质量也存在上游劣数据的实证（见 4.4）。适合做数据广度补充，不适合做单一回测主源。
- **tushare pro**：A 股数据质量与标准化的标杆，唯一普遍提供**实际公告日（ann_date）**的源，分钟线全档位、单次 8000 行；代价是积分制门槛。知乎 2026-08 横评结论与之呼应："Tushare Pro 强在 A 股数据质量与标准化" [#28]。
- **baostock**：历史回测零门槛与稳定的首选，免注册、T+1 更新、自带复权因子接口；短板是无 1 分钟线、财报无实际公告日字段 [待验证]。横评称其"强在历史回测零门槛与稳定" [#28]。
- **efinance**：接口顺手、返回即用，但纯东财上游使其成为 2025 年中限流事件的最大受害者（见第 7 章），只宜作辅助源。
- **mootdx**：被低估的稳定路线——通达信协议不走东财/新浪，本地 .lc1/.lc5 分钟线 + 官方网盘全历史分钟数据下载可自建完整分钟库；工程量大于前述源。
- **qlib 数据**：适合直接喂 Qlib 框架做 ML 选股，但覆盖与更新频率对独立量化研究不友好，本文仅作边缘候选。
- **新浪/腾讯 Direct**：实时快照的好来源，历史深度太浅且无契约保障，仅建议做实时补充与跨源校验。

## 3. 五维评估框架

知乎五大维度测评提出按**覆盖度 / 质量 / 稳定性 / 成本 / 易用性**五维评价数据源 [#29]。本指南针对**个人中低频量化**场景给出权重建议：

| 维度 | 建议权重 | 涵盖内容 | 理由 |
|---|---|---|---|
| 覆盖度 | **25%** | 证券范围、时间深度（尤其**分钟线深度**）、接口广度 | 中低频回测最怕"回测到一半发现历史分钟数据只有 5 天"；深度不足的源一次除权验证就会露馅 |
| 质量 | **25%** | **复权正确性、公告日字段**、OHLC 一致性、缺失率 | 复权算错 = 虚假收益曲线；公告日缺失 = PIT 回测前视偏差。质量错误比数据缺失更致命，因为它不报错、只骗人 |
| 稳定性 | **20%** | 上游限流、封禁风险、接口契约变动 | 增量更新被打断会污染本地库；efinance 限流事件证明免费爬虫源的稳定性不可默认 |
| 成本 | **15%** | 积分/年费、机器与存储成本 | 个人可承受 200-500 元/年量级，但 0 元方案仍是硬指标 |
| 易用性 | **15%** | 注册门槛、返回格式、文档完备度 | 工程手段（缓存/封装）可弥补，故权重最低 |

**加权结论**：tushare pro（质量+覆盖）与 baostock（成本+稳定零门槛）得分领先；akshare 以广度取胜但质量与稳定性被上游拖累；efinance 因限流事件稳定性失分明显。该排序与知乎横评结论基本一致 [#28]。

## 4. 复权质量专题

复权是 A 股数据源最容易"静默出错"的环节，单列一章。

### 4.1 前复权漂移机制（本地库头号杀手）

前复权以**最新价格**为基准向前推算历史价格。每当发生新的除权除息事件（分红/送转/配股），**全部历史前复权价格会整体平移**。后果：本地按前复权增量更新的数据库，在除权日之后与新下载的全量前复权数据**对不上**——旧缓存整体漂移，若不重灌全史则价格序列断裂。

博客园 2026-05-31 的一手踩坑记录证实：前复权增量更新导致历史价格整体平移漂移，正解是**后复权 + 单独存复权因子** [#12]。

### 4.2 后复权 + 存因子正解

- **原理**：后复权以**上市首日**为基准向后累乘，历史值永不变化，新除权事件只影响未来数据点——天然适合增量更新。
- **公式**（比例复权近似）：`后复权价 = 原始价 × 累计复权因子`；反向换算：`真实价 ≈ 后复权价 ÷ 当日因子`。
- **注意**：后复权价远大于真实价（老股票可达数千元），**展示、止损位、涨跌停判断必须换算回真实价**；回测收益率计算不受影响。
- **存储范式**：原始 OHLC 与 adj_factor 分表（或分列）存储，任何复权口径用时计算；增量更新只需追加当日因子行。社区亦有基于 tushare 本地库合成前后复权的开源实现可参考 [#30]。

### 4.3 各源复权因子接口现状

| 数据源 | 复权因子接口 | 现状与门槛 |
|---|---|---|
| tushare pro | `adj_factor` | 官方每日全 A 因子，随积分可用，最稳定 ✅ |
| baostock | `query_adjust_factor` | 免注册可取，按日/按区间返回 ✅ |
| akshare | 腾讯/雪球系因子接口（如 stock_zh_a_daily 附带 qfq/hfq 因子） | 覆盖与口径随上游波动，具体接口名与稳定性 [待验证] |
| mootdx | 0.7.9 起提供复权因子接口（PyPI changelog）[#31] | 免费可取，配合本地通达信数据闭环 ✅ |
| efinance | 无独立因子接口，直接返回 qfq/hfq 价格 | 需自行反推因子 [待验证] |

### 4.4 akshare 东财复权质量实证

东财上游的复权数据存在可直接引用的质量瑕疵：

- 官方 data_tips 风险页载明：`stock_zh_a_hist` 取 600734 后复权 OHLC 出现**负值**——上游直接给错，akshare 无法兜底 [#19]；
- issue #3913（2023-06）报告 `hist` 接口返回错误 [#17]；
- issue #4351：实时行情接口**不提供后复权**，需手动除以因子拼装 [#18]。

**结论**：akshare 的复权链路质量受上游制约，任何严肃回测都应**跨源校验复权因子**（如与 baostock/tushare 因子抽样比对），不可单源信任。

**"小时级信号可行吗？"结论：**

- **回测**：可行，且有三条已验证路径——① tushare 积分档 `stk_mins` 全档位（8000 行/次）；② baostock 5min 线聚合为 60min（零成本，牺牲 1min 粒度）；③ mootdx 本地 .lc5 + 通达信官方网盘全历史分钟数据自建完整库 [#32]。

## 6. 财报公告日字段与 PIT 对齐

PIT（Point-In-Time）回测要求"回测时点只能看见当时已公开的信息"，公告日字段是财务数据可用性的核心。

| 数据源 | 实际公告日字段 | 说明 |
|---|---|---|
| tushare pro | ✅ 财务接口普遍带 `ann_date`（实际公告日期）；另有 `disclosure_date` 披露计划接口（2000 积分/单次 6000 行）[#21][#22] | 唯一体系化提供公告日的源 |
| baostock | ❌ 季频财报无实际公告日字段 [待验证] | 只有报告期，需降级对齐 |
| akshare（巨潮源） | ⚠️ 可从巨潮资讯接口取公告日期，但稳定性一般 [待验证] | 可作辅助，不宜主用 |
| mootdx（affair） | ⚠️ 200+ 财报指标，公告日字段情况 [待验证] | — |

**PIT 对齐路径与降级方案：**

1. **首选**：用 tushare `ann_date` 逐条对齐——财报信息在 `ann_date` 当日收盘后才可用（或按 ann_date 当日起算，口径需在回测引擎内固定）。
2. **降级**（公告日缺失时）：用 **"报告期 + 法定披露截止日"保守对齐**——A 股季报法定披露截止为一季报 4-30、半年报 8-31、三季报 10-31、年报次年 4-30 [#33]。即假设该报告期数据直到法定截止日才可见。代价是丢掉最多约 4 个月的"真实可见窗口"，但**保证零前视偏差**——回测宁可保守，不可偷看。

## 7. 稳定性与限流

- **东财系 2025 年中限流事件**：efinance issue #215（2025-06-07）标题即"被东方财富针对了"——限流 + 滑块验证码 [#26]，另有腾讯云社区文章作第二来源 [#27]。akshare 同期 issue #5971 显示分钟线东财上游窗口缩短至约 5 个交易日 [#16]。**结论：所有以东财为上游的源（akshare 东财系接口、efinance）共享同一风险敞口，限流是平台级而非单库级。**
- **baostock 官方限流**：官网专设"平台访问规则"页（受限 IP 展示机制，属官方限流的直接依据）[#23]；多线程爬取被封有两源记录——CSDN 2021-12-07 [#24] 与知乎 2025-03-05 [#25]。**结论：免注册不等于无限制，QPS≈20、T+1 更新是官方约束，串行 + 重试是唯一正确姿势。**
- **双源互补实证**：tushare issue #1857 记录双源整合将数据可用性从 85% 提升至 99%+ [#9]——这是"任何单一免费源都不足以支撑严肃回测"的定量证据。

**工程结论**：免费数据源架构必须是"主源 + 校验源"双链路，本地缓存兜底，任何一天的两源差异都应触发告警而非静默覆盖。

## 8. 分场景推荐组合

### 场景 A：纯日线低频（目标成本 0 元）

- **组合**：**baostock 主源**（日线 + 复权因子 + 免注册）+ **tushare 免费积分档校验**（日线抽样比对）。
- **缓存策略**：SQLite/Parquet 存原始 OHLC 与 adj_factor 分列；每日收盘后 T+1 拉取，串行 + QPS 限速 + 断点续传；除权日全量重刷当日因子。
- **成本**：0 元；日维护工时约 5 分钟。

### 场景 B：日线 + 小时级回测（目标成本约 200-500 元/年 [待验证]）

- **组合**：**tushare 2000 积分档主源**（分钟线全档 + 财务公告日 ann_date，PIT 正解）+ **baostock 5min 备份**（聚合 60min，双源校验）+ **mootdx 本地库**补全历史分钟深度。
- **缓存策略**：tushare 按 8000 行/次分页落库，分钟线按月分区存储；公告日表与行情表分离；每季度用 baostock 抽样 50 只股全字段比对一次。
- **成本**：tushare 积分年费约 200-500 元 [待验证]，其余 0 元。

### 场景 C：未来扩展实时/自建全量（0 元，高工程量）

- **组合**：**mootdx/pytdx 实时快照**（通达信协议，不经东财/新浪）+ **通达信官方历史分钟数据网盘全量下载**自建 .lc1/.lc5 库 [#32] + akshare 做另类数据补充。
- **缓存策略**：网盘数据按季更新落库，盘中增量由 pytdx 补齐；建立日终对账任务（本地库 vs baostock 日线收盘价）。
- **成本**：0 元 + 服务器/存储自担；工程量最大但稳定性自主可控。

## 9. 统一实测方案

正式选型前建议用同一脚本对候选源跑一轮可复现实测。

**股票池**：全 A 按市值/行业分层抽样 200 只 + ST 股 10-20 只 + 上市不足 1 年新股 10 只 + 长停牌（连续停牌 >3 个月）5-10 只。

**测试区间**：① 2015 股灾（2015-06 ~ 2016-01，高波动 + 大量停牌）；② 2024-09 行情（2024-09-18 ~ 2024-10-08，极端涨跌停潮）；③ 2024-04 新国九条后（2024-04-12 ~ 2024-12-31，退市新规下 ST 行为变化）。

**四专项测试与验收标准**：

| 专项 | 方法 | 验收标准 |
|---|---|---|
| 复权一致性 | 同日同源双取（行情接口 vs 因子接口）+ 跨源因子抽样比对（tushare↔baostock） | 因子相对误差 < 0.1%；复权价隐含因子与因子接口偏差 < 0.1% |
| 停牌日 | 对长停牌股逐日核对交易日历 | 停牌日无脏数据行（无假 OHLC）；复牌日跳空连续可解释 |
| 公告日 | 抽样 50 只股 × 4 期财报，与巨潮公告页人工核对 | ann_date 一致率 100%（无公告日源验证降级方案是否保守） |
| 增量成功率 | 连续 20 个交易日每日增量拉取并比对全量重灌 | 成功率 ≥ 99%；差异自动告警且次轮自愈 |

**伪代码**：

```python
pool = stratified_sample(all_a, n=200) + st_list(15) + new_stocks(10) + long_suspended(8)
for src in [akshare, tushare, baostock, efinance, mootdx]:
    for code in pool:
        raw   = src.daily(code, start, end)                    # 不复权
        fac   = src.adjust_factor(code, start, end)            # 因子
        hfq   = src.daily(code, start, end, adjust="hfq")
        assert max(abs(hfq.close/raw.close - fac)) < 1e-3      # ① 复权一致性
        assert no_dirty_rows(raw, calendar, suspended_days)    # ② 停牌日
    for code, period in sample(pool, 50, periods=4):
        assert src.ann_date(code, period) == cninfo_date(code, period)  # ③ 公告日
    for day in trading_days(20):
        ok = incremental_pull(src, pool, day)
        success_rate.append(ok)                                # ④ 增量成功率
assert success_rate >= 0.99
```

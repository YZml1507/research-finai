## 1. 为什么"框架级口碑"不够，要看代码级行为

**框架选型中最常见的错误，是把"star 多不多、更新勤不勤、社区大不大"当成了回测可信度的判据。** 这三者衡量的是工程质量与生态，而回测结果是否可信，取决于撮合引擎对交易规则的建模精度——这是两件完全不同的事。

A 股恰好是全世界"规则密度"最高的市场之一，以下三条规则任何一条处理失真，回测净值都会系统性偏离实盘：

- **涨跌停**：价格触板后并非"想成交就能成交"。涨停板上有巨量封单时买入委托排队大概率轮不到你；跌停板上卖出委托同理。回测引擎若把涨跌停日当成普通交易日撮合，会在最极端、策略最需要验证的日子给出完全虚假的成交。
- **T+1**：当日买入的股票当日不可卖出（资金却是 T+0 可用）。日内回转类策略、打板策略若无 T+1 约束，回测会"免费"获得现实中不存在的平仓逃生通道，最大回撤被严重低估。
- **停牌**：停牌期间无成交、无价格。回测若用前值填充，就会在停牌日产生"假成交"；若直接跳过，又可能改变调仓节奏。两种做法都是对现实的近似，必须显式选择并知晓其代价。

**backtrader 是这个问题最典型的反面教材**：知乎专文《backtrader 最大的坑：没有内置处理涨跌停板》实测指出，backtrader 的市价单在下一根 bar 的 open 价照常成交——**涨停照买、跌停照卖**，回测严重失真[来源 7]。这意味着一个 23,002★（2026-08-28 GitHub 实测快照）的"明星框架"，在 A 股场景下默认给你的是一套假回测：**它不会报错、不会警告，只会安静地替你成交现实中根本不可能成交的订单。**

这正是本文的方法论：**不看 README 怎么说，看撮合代码在涨跌停/停牌/T+1 这些边界条件下到底怎么记账。** 差之毫厘（一单假成交），谬以千里（整条净值曲线失真）。

## 2. 对比维度定义：9 项 A 股关键规则

以下 9 项是 A 股回测与实盘差异的主要来源，也是本文的对比坐标系。每项给出定义与"正确行为"，第 5 章的验证用例将直接引用。

| # | 维度 | 定义 | 正确行为（回测应做到） |
|---|------|------|------------------------|
| 1 | **T+1** | 当日买入的仓位当日不可卖出 | 当日买入部分卖出委托应被拒单或挂起；当日卖出原有持仓的资金当日可用（资金 T+0） |
| 2 | **涨跌停** | 主板 ±10%（ST ±5%，创业板/科创板 ±20% 等） | 触板方向委托应拒单或不成交；撮合价不得超出涨跌停价范围 |
| 3 | **停牌** | 停牌日无行情、不可交易 | 停牌日委托不得成交；持仓按规则冻结；复牌首日恢复正常撮合 |
| 4 | **分红除权** | 除权除息日价格跳调、送转股、现金分红 | 持仓数量与成本相应调整、分红现金入账；净值曲线不得出现除权跳空假亏损 |
| 5 | **ST 档位** | ST/*ST 涨跌幅 ±5%，与普通标的档位不同 | 按标的属性应用不同涨跌幅档位 |
| 6 | **整手 100 股** | 买入须为 100 股整数倍（卖出可零股清仓） | 下单量校验按手数规则执行 |
| 7 | **tick_size** | 价格最小变动单位 0.01 元 | 撮合/滑点计算不得产生非法价格；边界判断应有容差 |
| 8 | **费用计入** | 佣金、印花税（卖出）、过户费 | 回测成交须扣减真实费用结构，而非零费率或统一费率了事 |
| 9 | **数据源绑定 + 许可** | 框架是否绑定特定数据源；开源许可是否允许商用 | 数据可自主更新、许可与用途匹配 |

**评级口径**（用于第 4 章矩阵）：**原生支持** = 默认行为正确；**需配置** = 框架内建但须显式开启/传参；**需自写** = 框架不含，须在策略层或修改引擎实现；**不支持** = 架构层面难以实现。对证据不足的维度，本文标注 **待验证** 而不是猜一个结论。

## 3. 逐框架代码级证据

### 3.1 rqalpha

**架构一句话**：米筐开源的事件驱动回测框架，mod 插件体系 + 内置 A 股交易语义（`mod.rs` 撮合/`mod.account` 账户体系按 A 股规则建模），数据绑定米筐 bundle。

**项目状态**：6,730★（GitHub 实测 2026-08-28），PyPI release 6.3.0（2026-07-23 发布），持续活跃[来源 1/4]。

**逐维度证据**：

- **T+1**：**原生支持**。T+1 是 rqalpha 的内置交易规则而非用户配置项；官方 CHANGELOG 显示其 T+1 逻辑经历过一轮重构（去除 hard code，改为更通用的规则建模）[来源 2，具体版本号待验证，见第 7 章]。知乎 2026-01 十工具横评的直接结论："**Rqalpha 对 A 股的支持最好，没有之一，内置 A 股交易规则（T+1、涨跌停、分红除权）**"[来源 6]。
- **涨跌停**：**原生支持**，且是四个框架中证据最硬的。官方更新履历逐条可查[来源 3]：
  - 滑点计算增加对涨跌停价的判断——**有涨跌停价的合约，滑点后的成交价不会超出涨跌停价范围**（防止滑点模型把成交价算到涨停板之上）；
  - 涨跌停边界撮合修正——**是否触及涨跌停的判断改为按 tick_size 做容差处理**（避免 9.99 vs 10.00 这类浮点边界误判）；
  - **获取到的涨跌停价为 NaN 时，认为标的没有涨跌停限制**（对无涨跌停品种的防御性处理）。
  以上三条均已在 2026-08-27 检索快照中逐条命中（rqalpha v6 线更新履历，readthedocs + GitHub releases 双源一致）。此外米筐商业版 rqalpha-plus 早在 2021-12 就把 signal 模式下超出涨跌停价格范围的订单从"仅打 warning"升级为"直接拒单"[来源 5]，说明涨跌停拒单语义在其撮合体系中是一等公民。
- **停牌**：**原生支持（细节待验证）**。米筐 bundle 自带停牌信息，策略层可查询；但开源版撮合器对停牌日委托的默认行为（拒单 vs 挂起）未见权威条目，列入第 7 章实测项。
- **分红除权**：**原生支持**。知乎横评明确点名"内置分红除权"[来源 6]。
- **ST 档位**：**待验证**。A 股规则体系内置的合理推论是支持（档位由 bundle 数据驱动），但未见直接条目。
- **整手 100 股**：**原生支持（细节待验证）**。A 股下单手数校验属于其内置交易规则范畴。
- **tick_size**：**原生支持**。见上文"涨跌停边界按 tick_size 容差处理"[来源 3]。
- **费用计入**：**需配置**。佣金/印花税/过户费可通过配置项显式设置，默认值需在 Phase 2 核对。
- **数据源绑定 + 许可**：**这是 rqalpha 的两个主要代价**。① 数据绑定米筐 bundle：bundle 免费下载，但**数据更新依赖社区维护节奏**，不接自家数据管线就要自建更新方案[来源 1/4]；② 许可为 Apache-2.0 **附加非商业条款**，PyPI 页面明示"仅限非商业使用"[来源 4]，商用前必须读 LICENSE 原文。

**已知坑**：① 非商业许可条款容易被忽视；② bundle 更新时效不受官方 SLA 保障，停牌/退市等数据质量取决于 bundle 维护方；③ 版本迭代快（6.x 线），策略 API 偶有破坏性变更。

**适用判断**：**A 股回测长期内核的首选**。撮合引擎对 A 股边界条件的处理是四者中唯一有官方逐条记录的。代价是非商业许可 + 数据绑定，个人研究/学习场景完全无碍。

### 3.2 backtrader

**架构一句话**：通用事件驱动回测框架，broker 撮合按"通用市场"设计（以美股语义为默认），A 股规则几乎全部外包给用户自行实现。

**项目状态**：23,002★（2026-08-28 GitHub 实测快照）但**实质停更**——最后实质提交 2023-04，repo 最后 push 2024-08-19，PyPI 停在 1.9.78.123（2023-04-19）[来源 11]。社区续作：smalinin/backtrader_next（48★，v2.3.7，2026-07 仍活跃）与 PyPI backtrader2（2020-07 后停滞）[来源 10]——续作体量与原版社区不在一个数量级，难以承接生态。

**逐维度证据**：

- **涨跌停**：**不支持，需自写**。这是 backtrader 在 A 股最著名的坑：知乎专文实测——**市价单在下一 bar 的 open 价照常成交，涨停照买、跌停照卖，回测严重失真**[来源 7]。云金杞《【思考14】涨跌停的处理方式》给出了两条补丁路线并对比成本[来源 8]：① **改底层撮合**（继承 BackBroker 重写撮合逻辑，最完美但费时，要吃透 backtrader 内部撮合代码）；② **策略层过滤**（下单前自查价格是否触板，触板日不发单）。结论：两条路都要用户自己动手，框架层面零帮助。
- **T+1**：**不支持，需自写**。broker 无仓位冻结期概念，需在策略层自行记录"买入日期"，或改写 broker 的 `submit/accept` 流程。未见官方支持条目。
- **停牌**：**不支持，需自选方案**。社区长期存在两派做法[来源 9]：**前值填充派**（pandas ffill 补齐 K 线，图好画但停牌日会产生假成交）vs **跳过派**（停牌日无 bar，但会打乱基于 bar 计数的调仓逻辑与指标窗口）。框架对两者都无内建支持，选择权与风险全在用户。
- **分红除权**：**不支持，需外部数据**。框架无公司行动（corporate action）模型，惯例是用前复权数据绕过——但前复权数据会让历史持仓成本失真，且除权日当天的现金分红不会入账。
- **ST 档位**：**不支持**。无标的属性体系，涨跌幅档位无从谈起。
- **整手 100 股**：**需自写**。下单量校验是通用 size 语义，无 A 股手数规则。
- **tick_size**：**不支持**。价格连续处理，无最小变动单位约束（这也是涨跌停 tick 容差问题在 backtrader 中根本不存在的原因——它压根不检查）。
- **费用计入**：**需配置**。`CommissionInfo` 通用佣金方案可配固定额/百分比，但 A 股"卖出印花税 + 买入无印花税"的非对称结构需要自己写子类。
- **数据源绑定 + 许可**：**无绑定（优势）+ 许可待复核**。通用数据 feed 接口配 akshare/pandas 很方便，这是它作为教学框架的价值；许可条款本文未做核验，列入第 7 章。

**已知坑**：① 上述全部 A 股规则缺位且**无警告**——这是最危险的，错误是静默的；② 停更 3 年+，issue 区积累的 A 股相关 bug 不会有人修；③ 大量中文教程演示的"完整回测"实际都跑在无涨跌停约束的默认 broker 上，初学者照抄即中毒。

**适用判断**：**仅适合作教学件，且必须补"自写涨跌停过滤"前置课**（详见第 6 章修正点 1）。作为生产回测内核不推荐——不是因为老了，而是因为它的错误是静默的。

### 3.3 vnpy

**架构一句话**：全功能量化交易平台（Gateway 接入 / OMS / CTA 引擎 / 事前风控一应俱全），回测是平台的一个模块而非全部。

**项目状态**：44,821★（GitHub 实测 2026-08-28），PyPI v4.4.0（2026-05-14），要求 Python ≥ 3.10，迭代活跃[来源 12/13]。

**逐维度证据**：

- **旧 CTA 回测引擎（vnpy 4.x 之前的主力回测路径）**：**对 A 股日线场景基本不可用**。官方论坛结论：CTA 回测引擎**至少需要 1 分钟线或 tick 数据，日 K 无法直接回测**[来源 19]；且为单标的引擎，多标的截面策略支持有限[来源 20]。这与其期货 CTA 基因一致——引擎按期货 T+0、无涨跌停拒单语义的默认世界观设计，A 股规则不是它的设计目标。
- **新版 Alpha 回测引擎（2025 年起）**：**关键新变量**。VeighNa 4.0.0 新增面向 AI 量化策略的 `vnpy.alpha` 模块，提供从多因子机器学习策略研发到实盘的一站式方案[来源 16]。官方《VeighNa 多因子入门系列》**第 6 篇《事件驱动历史回测》**（vnpy 官方论坛，2026-06-01）明确描述其日频截面回测机制[来源 15]：**"对日频截面策略来说，可以把每个交易日理解为一个事件：回测引擎推进到某个交易日，引擎取出该日所有标的的 K 线切片，已经挂出的委托先尝试撮合……"** ——即 **日线、多标的、事件驱动回测已在官方引擎层面实现**。前任调研者记录的"撮合含涨跌停约束"说法与该系列定位吻合，但**逐字条目未能在本轮检索中直接命中**，作为部分确认列入第 7 章待验证。
- **T+1 / ST / 整手**：**待验证**。Alpha 引擎面向多因子选股的周/日频调仓场景，其撮合细则（T+1 约束、手数取整、费用模型）官方文档未逐条列出。
- **分红除权**：**待验证**。多因子系列第 2 篇涉及 AlphaLab 数据准备，复权处理方式需核对原文。
- **费用计入**：**需配置**。合约属性（费率 rate / 合约乘数 size）通用建模，A 股费用结构可配。
- **数据源绑定 + 许可**：**无绑定 + MIT（优势）**。数据服务可插拔（迅投研/ DolphinDB / 纸鸢等均有适配），股票数据方案官方有专文[来源 16]；MIT 许可无商用障碍。

**已知坑**：① **两代回测引擎并存易混淆**——网上大量教程仍基于旧 CTA 引擎写"日 K 回测"，照抄会撞上"不支持日 K"或被迫用 1 分钟数据合成；② Alpha 引擎定位于多因子截面场景，**单标的、日内、CTA 型的 A 股日线策略并不因它的出现而变得可回测**；③ 平台重（Python≥3.10、依赖多），只为回测而装 vnpy 属于杀鸡用牛刀。

**适用判断**：**"回测 + 实盘一体化"路线的可行选项**——尤其当你本来就打算用 vnpy 做实盘（其 Gateway/OMS/事前风控是四者中最强的[来源 12]），2025 年后的 Alpha 引擎把多因子类 A 股日频策略的回测短板补上了。但若只为回测，它不是最短路径。

### 3.4 hikyuu

**架构一句话**：C++ 内核 + Python 接口的量化框架，自带本地数据管理工具，从数据到撮合全栈自持。

**项目状态**：3,472★（GitHub 实测 2026-08-28），PyPI v2.8.2（2026-08-19），活跃迭代[来源 17/18]。社区规模中等偏小，中文资料以官方文档与作者（fasiondog）输出为主。

**逐维度证据**：

- **A 股适配定位**：官网 hikyuu.org 自述**"深度适配国内 A 股市场"**[来源 17]——这是四者中唯一把 A 股适配写进官网定位语的。
- **数据源绑定**：**自有本地数据方案**。自带数据导入/管理工具（支持从通达信等本地数据源导入），数据完全本地自持，不依赖云端 bundle 更新节奏——对数据自主权要求高的用户这是独特优势。
- **性能**：**C++ 内核带来显著速度优势**，批量标的、长周期回测场景的吞吐能力在四者中占优（同量级任务 Python 引擎需分钟级者，C++ 内核常为秒级——量级描述，非基准测试数据）。
- **T+1 / 涨跌停 / 停牌 / 除权 / ST / 整手 / tick_size**：**撮合细节待验证**。官网定位语与"深度适配 A 股"的社区口碑指向内建支持，但**撮合器对涨跌停拒单、T+1 冻结的具体实现细节，本轮未取得代码级或官方文档级证据**，全部列入第 7 章待验证清单——本文拒绝在没有证据的情况下替 hikyuu 背书这些维度。
- **费用计入**：**待验证**。
- **许可**：**待复核**（本轮未核验 LICENSE 原文）。

**已知坑**：① 社区小 → 遇到撮合层 bug 时可参考的讨论少；② C++ 内核意味着出问题时调试门槛高于纯 Python 框架；③ 学习曲线包含其自有概念体系（System/Strategy/AllocateFunds 等），迁移成本高于通用框架。

**适用判断**：**高性能 A 股本土化备选**。适合：数据要本地自持、标的池大（数百~数千只）、对回测速度敏感的用户。不适合：需要大社区兜底、以通用量化知识（而非 hikyuu 特有概念）为主要学习目标的初学者。

## 5. 五个"必挂"验证用例集（供 Phase 2 实测）

设计逻辑：**每个用例都构造一个"框架默认行为大概率做错、而正确答案唯一且已知"的场景**。用例在框架上运行后，对照"预期正确行为"逐条打分；任何一个用例失败，该框架的回测结果就不应被信任。用例数据建议取自真实历史（如 2015 股灾熔断段、2024-02 微盘股流动性危机段，涨跌停/停牌密度高）。

### 用例 1：涨停买入

- **构造**：某标的连续两日一字涨停（开盘即封板、全天未开板），策略在第二日开盘发出市价买单。
- **预期正确行为**：委托被拒单或全天不成交（一字板排队成交概率趋近于零）；无论如何，**成交价不得高于涨停价**，且次日不应产生"当日买入的浮盈"以外的假收益。
- **判定标准**：✅ 通过 = 无成交或有条件的部分成交；❌ 挂 = 以开盘价/涨停价正常成交（backtrader 已知会挂[来源 7]）。
- **已知预判**：rqalpha 应通过（滑点限幅 + 涨跌停撮合约束[来源 3]）；backtrader 默认必挂；vnpy/hikyuu 待实测。

### 用例 2：跌停卖出

- **构造**：持仓标的当日一字跌停（开盘即封死跌停），策略开盘发出市价卖单。
- **预期正确行为**：委托拒单或不成交；账户净值应体现"想跑跑不掉"的真实状态，而不是按跌停价顺利清仓。
- **判定标准**：✅ 通过 = 无成交；❌ 挂 = 按跌停价成交、顺利止损。
- **意义**：这是对最大回撤影响最大的用例——流动性危机段的回测若在跌停日顺利清仓，回撤会被系统性低估，风控参数（止损线）会设得过于激进。

### 用例 3：停牌日下单

- **构造**：持仓标的停牌 3 个交易日（无行情），期间策略发出卖单；第 4 日复牌（假设复牌首日大跌）。
- **预期正确行为**：停牌期间委托不成交（拒单或挂起至复牌）；复牌首日按复牌价撮合；持仓在停牌期间市值冻结而非按前值波动。
- **判定标准**：✅ 通过 = 停牌期零成交、复牌日正常撮合；❌ 挂 = 停牌期出现按前收盘价计的"成交"（前值填充派框架的典型假成交）。
- **附带检查**：净值曲线在停牌 3 日内应是水平线（而非按前值重估产生的锯齿）。

### 用例 4：除权日持仓

- **构造**：持仓标的实施 10 送 10（股本翻倍、价格腰斩）+ 每股派现 0.5 元，除权除息日持仓不动，策略不做任何操作。
- **预期正确行为**：持仓数量翻倍、现金入账分红、持仓成本相应摊薄；**账户总资产连续无跳变**（除权本身不创造也不毁灭价值）。
- **判定标准**：✅ 通过 = 总资产曲线平滑、股数变 2 倍、现金增加；❌ 挂 = 总资产在除权日出现约 -50% 的"假崩盘"（框架只调价格不调股数的典型症状）。
- **意义**：该用例一票否决式暴露框架的公司行动建模能力。用前复权数据绕过除权的方案在此用例下会暴露成本失真问题。

### 用例 5：T+1 当日买卖

- **构造**：T 日 09:35 买入某标的 1000 股（非底仓），T 日 14:50 发出同标的 1000 股卖单（卖的是当日买的那部分）。
- **预期正确行为**：卖单被拒（可卖数量为零）或部分成交（若账户恰有底仓则底仓部分可卖）；**当日买入部分绝不可当日卖出**。
- **判定标准**：✅ 通过 = 拒单或仅底仓部分成交；❌ 挂 = 1000 股全额成交、当日回转成功。
- **意义**：直接检验框架仓位账本是否带"买入日期"维度。这也是日内止损策略回测失真的头号来源——回测里能跑掉的止损，实盘 T+1 跑不掉。

**用例集使用建议**：五个用例合计不到 50 行策略代码，但对四个框架各跑一遍即可生成一张"实测版第 4 章矩阵"，把本文所有 ❓ 变成 ✅/❌。这是本系列 Phase 2 的最高优先级任务之一。

## 6. 混合方案与选型建议：对既有推荐的互证与修正

01/03 号文档给出的推荐链路是：**akshare 取数 → backtrader 作入门过渡（学完即换）/ rqalpha 作 A 股回测长期内核 → miniQMT 下单**。本轮代码级调研的结论：**主链路成立，但有一处必须修正、一处可以扩展。**

### 修正点 1：backtrader "入门过渡"必须加前置课，否则学到的是假回测

**原推荐的隐患**："backtrader 作入门过渡"隐含假设是"入门学到的回测方法论可以无损迁移"。但第 3.2 节证据显示，backtrader 默认 broker 在涨跌停/T+1/停牌上全部静默失真[来源 7/8/9]——**初学者用它跑通的第一个"成功回测"，大概率包含现实中不可能的成交**。以错误的心智模型入门，迁移时先要"消毒"，成本反而更高。

**修正后的推荐**：backtrader 仍可作入门件（生态教程最丰富、概念抽象干净，这些优势真实存在），但**入门路径必须插入一节"自写涨跌停过滤"前置课**——按云金杞给的策略层过滤路线[来源 8]，下单前检查次日目标价是否触板、触板不发单，半小时工作量即可让入门回测不再中毒。**原推荐中的"学完即换"节奏不变**，rqalpha 接棒位不变。

### 互证点 2：rqalpha 内核推荐成立，且比原推荐更有底气

原推荐把 rqalpha 定为 A 股回测长期内核，主要依据是口碑（"对 A 股支持最好"）。本轮下潜到代码级后，该判断不仅成立，而且证据质量升级：**T+1 重构去 hard code、滑点不超涨跌停价、tick_size 容差边界撮合、NaN 涨跌停价防御**四条官方更新记录逐条可查[来源 2/3]，是四框架中唯一有官方逐条 A 股边界条件处理记录的。需附带两个使用注意：**① 非商业许可**（商用必须换方案或谈授权[来源 4]）；**② bundle 数据更新依赖社区**，生产级使用建议自建数据管线喂入。

### 扩展点 3：vnpy 一体化路线从"不推荐"升格为"可行备选"

原推荐隐含把 vnpy 排除在回测内核之外（这是对的——旧 CTA 引擎不支持日 K[来源 19]）。但 2025 年后的变化改变了局面：VeighNa 4.0.0 新增 `vnpy.alpha` 模块[来源 16]，官方多因子系列第 6 篇确认**日线、多标的、事件驱动回测**已在官方引擎层落地[来源 15]。**若你的目标策略是多因子截面型 A 股日频策略，且计划用 vnpy 做实盘（其 Gateway/OMS/事前风控是四者最强），那么"vnpy 一体化（回测+实盘同一平台）"可以省掉回测引擎与实盘框架之间的策略翻译成本**——这是 rqalpha + miniQMT 链路做不到的一体化深度。

**两条路线的决策规则**：

- 策略形态为多因子截面、本来就打算 vnpy 实盘 → **vnpy 一体化路线**；
- 其他情形（单标的择时、事件驱动、日内、或实盘走 miniQMT）→ **rqalpha 内核 + miniQMT 链路不变**；
- hikyuu 作为高性能/数据自持特化选项保留在备选位，待第 5 章用例实测其撮合细节后再定去留。

### 修正后的总推荐

| 场景 | 推荐 | 理由 |
|------|------|------|
| 纯入门学习 | akshare + backtrader（+ 自写涨跌停过滤前置课） | 教程生态最厚，但必须先消毒 |
| A 股回测长期内核（个人研究） | akshare/rqalpha bundle + rqalpha | 唯一全维度代码级验证的 A 股适配 |
| 多因子截面 + vnpy 实盘意向 | vnpy.alpha 一体化 | 回测实盘同平台，省策略翻译 |
| 大标的池 + 数据自持 + 性能敏感 | hikyuu | C++ 内核 + 本地数据，撮合细节待实测 |
| 商用场景 | ⚠️ rqalpha 受非商业许可限制；vnpy(MIT)/hikyuu(待核)/backtrader(待核) 优先复核许可 | 见第 4 章许可行 |

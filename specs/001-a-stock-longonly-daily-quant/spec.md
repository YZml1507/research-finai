## 1. 背景与目标

### 1.1 背景

- 已完成 4 轮调研（V5）：交易规则与成本（07）、监管与报备（11）、数据源实测（12）、回测框架 A 股适配（13）、坑集（08）、台账（14）。技术情报饱和。
- 硬件事实：初始资金 **10-15 万人民币**（成本测算取中位 12.5 万）；A 股做空/杠杆三道 50 万门槛不可达（上证发〔2023〕41号 第六条第二款），**v1 纯多头、无杠杆**。
- 长期规划：A 股先积累经验 → 美股 → 韩股（留口不实现，见 §3.3 与 constitution 原则五）。
- 第五轮（spec 阶段）：缺块 A 系统设计调研已完成（两底稿 14 主题），美股/韩股做空能力调研已完成（两底稿），结论并入本 spec（§3.3、§5、§7）。

### 1.2 目标（本 spec 覆盖的产物）

一套**单机 Windows + Python 3.11 + 免费数据源**的可运转量化研究/交易系统，支持：日线数据管道 → 策略研究（向量化快速迭代）→ 事件驱动正式回测（5 必挂用例全过）→ 绩效与风险评估 → 模拟盘（≥6 个月）→ 小额实盘（用户书面确认后）。回测与实盘行为同构；全程 0 元、单人可运维。

### 1.3 用户角色（spec-kit lean 适配）

| 角色 | 职责 | 主要触点 |
|---|---|---|
| **研究员** | 数据探索、策略 idea、回测实验、绩效与风控分析、结论入档 | 数据管道、回测引擎、绩效报告、实验 registry |
| **运维** | 数据更新调度、收盘日终任务、对账、告警处理、台账保鲜、合规报备 | 调度器、日终任务、日志与告警、14 号台账 |

（spec-kit 默认面向"终端用户"的故事在此项目不适用；用户即上述两角色的本人。）

## 2. 范围与边界

### 2.1 范围内（v1 必须交付）

- 数据管道：日线（前/后复权）、季频财报（pubDate 对齐）、股票池与成分回放、停牌/涨跌停/除权标记；三源（baostock 主 + 新浪/腾讯校验）。
- 事件驱动回测引擎：T+1、涨跌停/一字板不撮合、停牌不成交、费用模型（含最低 5 元佣金）、滑点、5 必挂用例测试套件（13 号）。
- 组合与风控：3-8 只（默认 5，硬上限 10）、单票建仓 ≥2 万、仓位管理器（择时空仓/减仓为一等公民）、止损/退出规则。
- 会计与对账：逐笔交易台账（不可变流水）、推导持仓/资金视图、券商交割单对账、净值曲线。
- 报告与归档：回测指标报告、实验 registry（参数/代码/数据版本可复现）、14 号台账衔接。
- 调度与运维：Windows 任务计划程序调度数据更新/日终任务、结构化日志轮转、幂等重跑、失败告警。
- 合规：程序化交易报备材料清单（11 号）、先报告后交易。

### 2.2 范围外（v1 明确不做，留扩展点）

- 做空/杠杆/两融（constitution 原则五；两融扩展点触发条件：资金 ≥50 万且策略实盘满 1 年）。
- 美股/韩股实盘接入（架构留口见 §3.3，留口 ≠ 实现）。
- 分钟线/小时级信号（实测仅 2020 年起约 6.5 年，v1 纯日线；不排斥未来作为研究扩展）。
- 高频交易、期货、期权、可转债等其它品种。
- 移动端/Web 界面（CLI + Markdown/HTML 报告即可）。

### 2.3 非目标（刻意放弃）

- 与商业平台（聚宽/米筐）的对标功能全量实现——只实现本项目所需子集。
- 通用回测框架的完整框架性（四人框架代码级对比结论见 13 号）。
- Dashboard/MLOps 类重型组件（constitution 原则十）。

> 深度终裁见下方注（调研已回归）；当前按 constitution 原则五执行——留口、不做实现：

> **多市场留口深度终裁（2026-08-29；`short_selling_us.md` v1.0 + `short_selling_kr.md` v1.0，双路互证）**：
> - **韩股**：散户做空现实性极低（2025-03-31 全标的恢复后首周散户仅占做空成交 0.85%；借券费率 3-8% 一刀切、券源稀缺；中国用户无中韩互联互通 + 个人购汇不得用于境外证券，投资本身即无合规通道）；替代路径完备（KRX 指数反向/杠杆 ETF：114800 KODEX 인버스 -1x、252670 -2x 等，买入即看跌，账本语义与普通多头同构）。→ **韩股扩展无需负仓位/做空账本**，仅需 `instrument_type` 分类字段（etf_inverse/etf_leveraged）+ 适当性/教育字段占位。注意 2026-07-31 起韩国收紧的是**单股**杠杆 ETF（预存金 3000 万韩元并停新上市），指数反向 ETF 不受影响。
> - **美股**：散户做空真门槛 = 保证金账户 + Reg T 150% 初始保证金（12 CFR 220.12(c)(1) 原文）+ FINRA 维持保证金 30%（4210(c)(3)）+ 个股可借；Reg SHO（17 CFR 242）locate 前置 + Rule 204 close-out + threshold（203(c)(6)）已提取官条文；**PDT 纠错**：$25,000 门槛系日内交易规则（5 个营业日 ≥4 次同证券日内买卖），非做空门槛（FINRA 4210(f)(8)(B)），且 **2026-06-04 起已废除**（SEC 2026-04-14 批准 SR-FINRA-2025-017，过渡至 2027-10-20）——中文资料引用已过时；hard-to-borrow 融券费率可达 54%-1000% 年化（按日 360 天计息含非交易日）。中国用户无合规通道（证监会 2016/2022 定性跨境展业非法、外汇局 5 万美元/年便利化额度不含证券投资）→ **做空现实性低**。

## 5. 系统设计决策（SDD）

> 本节为调研回填终版（底稿：`gap_a_backtest_live_parity.md` v1.0 / `gap_a_design_sweep.md` v1.0 / `short_selling_us.md` + `short_selling_kr.md` v1.0，检索日 2026-08-29）。原则十条中的不可协商项（PIT/数据卫生/成本/执行语义）不回填仅引用。

### SDD-1 回测-实盘同构：最小同构（Shared Core + Replaceable Broker）

- **否决**完整 LEAN 式引擎（C# 单体过重）也**否决**回测/实盘双写两套。
- 四环境（research / backtest / paper / live）共用同一**策略核**：`on_bar / on_order / on_trade / on_cancelled` 事件契约 + 账本（ledger）+ 订单状态机——只写一份（`gap_a_backtest_live_parity.md` 主题 1）。
- 差异全部收敛到 **Broker 一个接口**：
  - `BacktestBroker`：bar 级撮合（事件驱动，5 必挂用例由此验证）；
  - `PaperBroker`：影子撮合 + 真实行情；
  - `LiveBroker`：实盘桥（miniQMT/xtquant 或券商 API；xtquant 请求拒绝码 48-57/255 语义已取得迅投数据字典原文映射——255 未知态强制对账裁决）。
- **回测撮合器与实盘共享同一套 A 股语义函数**（涨跌停/停牌/T+1/整手）：价格来源可差、规则语义不可差。
- **时钟抽象** `TimeSource`：回测=日历推进，实盘=真实墙钟（调度触发）。
- 结算函数 `settle_day` 四环境共用（`FR-BT-4` 除权语义验证）。
- **实盘重启恢复**：按 nautilus 启动对账模式——券商三报告（成交/持仓/资金）→ 补齐事件 → 重放 → 校验；in-doubt 状态不猜测，转人工。
- 风险注：合约定案（账本/状态机/事件契约 Phase 2 就按四环境共用设计）**不可逆**，后补成本高。

### SDD-2 订单状态机与双账本 + 日终对账

- **统一状态机七态**：`PENDING_SUBMIT → SUBMITTED → (PARTIALLY_FILLED)* → FILLED / CANCELLED / EXPIRED / REJECTED`；回测拒单与实盘券商回报语义一致（xtquant 数值映射已取得原文）。
- **双账本**：append-only 流水（`Decimal` 字符串存储、`tx_hash` 幂等重放键）+ 可重算视图（持仓/资金/净值均为推导）；成交幂等键 `trade_id`、下单幂等键 `client_order_id`。
- **对账四态**（quant67 裁剪）：匹配/长款/短款/不一致；日终一次：券商 API 或交割单 CSV 解析 → 三表（成交/持仓/资金）匹配 → 差异进人工确认通道（`RECON_ADJUST` 只附加记账、不改流水）→ 报告 + 告警。
- ≤10 笔/日规模：脚本 + 报告即可，不平台化。
- 含"回测自对账"思想：`FR-BT-4` 除权用例本质即对账用例（账本重放 = 视图校验）。

### SDD-3 事件驱动 vs 向量化：全事件驱动单引擎

- **不做**研究层向量化 + 正式层事件驱动双轨：向量化优势（海量标的 × 参数网格）在本项目规模用不上；双轨引入的翻译成本与 5 必挂用例在向量化下必然做错（撮合语义全部是跨 bar 状态依赖）（IBKR 官方工程文为两范式分界证据）。
- 向量化仅保留为研发期 ≤20 行手写冒烟计算器，**其结论禁入策略评审**。

### SDD-4 模块总架构（开源裁剪结论）

- 单元（借鉴 LEAN/vnpy/nautilus/qlib/rqalpha 提炼，仅取思想不取代码）：`DataSource / FeaturePipeline(含数据字典) / SignalGenerator / PortfolioConstructor / OrderRouter / RiskManager` 六层 + `Broker(接口见 SDD-1)` + 运营四件套（调度/日志/告警/备份）。
- 回调契约统一：`on_bar / on_order / on_trade`（vnpy 式）——研究/回测/模拟/实盘四环境共用。
- **v1 明确不带**：事件总线重实现、第三方消息中间件、ORM、MLflow、Task 队列、分布式（`gap_a_design_sweep.md` 主题 1 YAGNI 剔除清单）。

### SDD-5 配置与实验管理

- 三层配置：`defaults(代码内) → user(TOML，pydantic-settings 加载，环境变量/`.env` 覆盖) → secrets(仅 env/`.env`，gitignore) `（12-factor 惯例；pydantic-settings + tomllib 官方文档佐证）。
- 实验 registry：轻量 QlibRecorder 式 — JSON 元数据 + HDF5 指标 + CSV 表格；`run_id` 钉扎 **代码版本(git hash) + 数据版本(数据快照 id) + 参数**（qlib 官方 Recorder 三层接口语义，MLflow 后端不引入）。
- 与 14 号台账/05 号来源记录衔接：registry 记录是纪律落地的工程面。

### SDD-6 单人运维落地

- 调度：Windows 任务计划程序（官方 `${LASTEXITCODE}` 结果码由计划程序记录可追溯）；任务：数据更新（盘后）、日终（对账/净值/报告）、周报。
- 日志：`logging` 官方 HOWTO 结构 — 级别/时间戳/模块/`run_id`；按日轮转 + 大小上限（`TimedRotatingFileHandler`）；敏感信息脱敏。
- 告警（FR-OPS-3）：**通道载体需用户拍板**；候选：邮件（既有邮箱）、Telegram bot（既有账号）等——不注册新账号，落地前不实施。
- 备份：代码+文档 git；数据 + registry 归档（内部盘点）；恢复演练一次/季（FR-OPS-5）。
- 运维 SOP 与 14 号台账衔接：到期提醒（月度 2026-09-28 / 季度 2026-11-28）纳入日终检查。

### SDD-7 多市场留口深度（终裁）

- 韩股：**无需负仓位/做空账本**（反向 ETF 视为普通多头标的；`instrument_type` 分类 + 适当性字段）；美股：**long-only default + 低成本留口**（OrderSide SHORT 枚举、带符号数量 v1 非负校验、流水枚举预留 INTEREST/BORROW_FEE/DIVIDEND、per-instrument 费率口径预留 360/365 与计息日类型）。
- **不做**：负数量撮合 / threshold·locate 规则引擎 / portfolio margin（YAGNI）。
- 详见 §3.3 终裁注；PDT 已废除（2026-06-04）事实在文档级结论中使用时须与现行文本双表述（底稿按新老两套表述）。

## 6. 验收标准（整体）

### 6.1 回测指标门禁（研究员角色）

- 策略进入模拟盘前须出具：收益/波动/最大回撤（含区间）/夏普/换手/费用明细/胜率，且：
  - 5 必挂用例全过（FR-BT-1~5）；
  - 回测费用与 07 号费率逐项核对通过；
  - 至少两段样外区间（如 2015-2016 股灾+熔断、2018 熊市）结果如实呈现，不选择性展示；
  - 参数稳健性：±20% 邻域扫描无悬崖（可早于模拟盘，作为研究门禁）。

### 6.2 工程指标门禁（运维角色）

- 数据管道：增量更新幂等、停牌过滤命中率 100%、跨源对账通过（FR-DATA 全绿）。
- 系统：日终任务 30 天内无无人值守失败未告警事件。
- 对账：模拟盘期间每日交割单对账零未解释差异（节假日顺延按规则）。

### 6.3 门禁顺序（constitution 原则八；用户指令 2026-08-29）

1. 本 spec 定稿（v1.0.0）→ plan/tasks → **停下询问用户是否同意开始建系统**；
2. 按 03 号 Phase 0-6 顺序执行，每阶段验收通过才进入下一阶段；
3. 模拟盘 ≥6 个月 → 用户书面确认 → 小额实盘（最小可验证资金）→ 加仓需再次确认。
